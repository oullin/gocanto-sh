## Findings considered and rejected / deferred

Recorded so nobody re-audits them:

- **vitepress 1.6.4 → vite 5 security floor**: real, but vitepress 1.x is
  hard-capped to vite 5; migration means a vitepress major upgrade. Deferred
  until vitepress 2.x is stable — revisit deliberately, don't force partial
  patches. (Audit ref DEPS-03.)
- **happy-dom vs jsdom "duplication"**: not removable — different roles
  (vitest env vs SSR/DOMPurify). No action. (DEPS audit.)
- **"Three search implementations"**: mostly false alarm — app search, domain
  corpus, and writing's filter serve different data/runtimes; the only overlap
  (writing's custom filter + VitePress local search) appears intentional.
  Optional one-line comment; not worth a plan. (DEBT-07.)
- **Presentational Vue components untested**: acceptable — logic lives in the
  well-tested domain package; coverage effort goes to logic paths instead.
  (TESTS audit.)
- **mailto CTAs instead of a contact form**: by-design for a personal site.
  (Direction audit.)
- **`sort` field for `profileSkillOrder` (46-UUID parallel array)**: real but
  small; silent-omission risk is mitigated by the build-time throw on unknown
  UUIDs. Fold into a future store cleanup if content editing gets painful.
  (DEBT-04 — no plan by prioritization, not by rejection.)
- **Eager workflow-tab data (~21 KB) / marquee off-screen animation /
  jsdom-in-bundle tripwire / `decodeHtmlEntities` parity tests /
  `computeLastmod` timezone parsing / URL-scheme allowlist for store hrefs /
  go-fmt image pinned to mutable tag / two resolved TS majors**: LOW-severity
